# 0.24.0 Release Plan

Version `0.24.0` promotes local agent persistence and application-owned catalog contracts to Stable, adds durable onboarding, hardens observability, and introduces exact-artifact provider certification controls. The distribution remains Beta.

## Compatibility and changes

- InMemory/SQLite agent run stores, local memory/checkpoint factories, `AgentMemoryState`, and `SummaryConfig` now follow the Stable compatibility policy. SQLite is single-host storage; applications serialize session updates and reconcile external effects. Existing imports and persisted formats require no migration.
- `ModelCatalog`, `ModelCatalogEntry`, `create_model_catalog`, and capability schemas become Stable. `ModelPricing` and catalog metadata aliases are now supported root imports. The maintained default snapshot and capability discovery remain Beta.
- Beta `zhivex init` scaffolds a durable application. Typed approval inputs survive restart and are validated again before execution. OTel emits allowlisted metadata without exception payloads.
- Development/CI dependency installs use `uv.lock`; Python 3.11 minimum/latest compatibility gates and scoped provider linting protect the supported dependency range. The default websocket transport now requires `pip install "zhivex-ai-sdk[realtime]"`.
- Certification controls distinguish source contracts, installed artifacts, and exact-wheel live operations. Historical 0.23.0 provider certification records and its pinned manual certification workflow remain evidence for 0.23.0 only.

## Validation

[Local candidate evidence and artifact hashes](0.24.0-evidence.md) record the completed release checks.

Run `make release-evidence` to collect a candidate report. The Stable Postgres run store also requires the PostgreSQL CI gate.

Use uv 0.12.4 (or newer as permitted by pyproject) and run `make release-check`. This checks the lock, tests/coverage, typing, support/certification schemas, wheel and sdist installs, optional extras, dependency audits, and metadata. CI additionally requires PostgreSQL-backed runtime and installed-workflow checks and the Python 3.11–3.14 matrix.

The new `0.24.0-smoke-policy.json` requires the exact installed 0.24.0 wheel and the existing OpenAI Luna / Meta Contributor synthetic operations. PyPI and TestPyPI workflows use this policy and validate fresh evidence before publishing. No historical result is certification of this candidate.

## Publication

1. Review and merge these changes, then wait for every main CI gate, including PostgreSQL and dependency compatibility.
2. Recheck that PyPI 0.24.0 and remote tag v0.24.0 are absent (both were absent during preparation).
3. Create the annotated `v0.24.0` tag on the approved clean main commit and push it once.
4. The protected workflow builds the distributions, runs exact-wheel live canaries, and publishes through Trusted Publishing.
5. Verify PyPI hashes and retain workflow evidence. Local preparation does not publish or create a tag.
