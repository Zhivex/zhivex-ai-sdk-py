# 0.22.0 Release Plan

Version `0.22.0` makes the maintained model catalog operational in gateway routing, corrects terminal attempt telemetry, and hardens generation-cache concurrency and file publication. The distribution remains Beta; this is a compatible minor release, not package-wide GA.

## Scope

- terminal `GatewayAttempt` and `on_attempt` telemetry with deterministic attempt IDs, typed error classes, sanitized errors, provider latency, and observer isolation
- typed catalog capabilities, target evidence, lifecycle-aware fallback scoring, conservative dated pricing, and fail-closed capability/budget enforcement
- refreshed default catalog with explicit aliases, provider sources, availability, lifecycle, and recommendation metadata
- concurrent cache-miss coalescing for in-memory and file-backed generation caches
- descriptor-aware validation and synced atomic replacement for file-backed cache entries

## Compatibility Boundary

- The documented Stable package-root export set is unchanged.
- Existing callers keep primary-target-first routing and the legacy fallback heuristic for uncataloged targets.
- `provider_costs_per_1k_tokens` remains accepted as the deprecated lowest-precedence compatibility fallback.
- The corrected `on_attempt` contract emits one terminal event per retry or skipped target; applications that interpreted the old premature success-shaped callback as a start event must move that signal to their application boundary.
- `ModelCatalog`, `ModelPricing`, and generation-cache helpers remain Beta and may evolve under the documented minor-release policy.
- File-cache JSON shape and factory signatures are unchanged; invalid entries now surface the existing public `ValidationError` instead of leaking parser/type exceptions.

## Required Evidence

- gateway regressions cover terminal events, typed errors, refusal semantics, latency, observer isolation, catalog scoring, capability skips, lifecycle penalties, alias pricing, and expired prices
- cache regressions cover concurrent coalescing, independent keys, waiter cancellation, downstream failures, atomic replacement, symlink/non-regular rejection, and bounded stale-temporary cleanup
- catalog validation proves canonical/alias uniqueness, immutable metadata, defensive copies, provider-source coverage, and normalized capabilities
- public contract, stability, support, production, observability, README, and changelog remain aligned
- the Stable Postgres run store and workflow persistence gates remain green in CI
- `make check` and `make release-check` pass for the exact candidate
- wheel and sdist metadata report exactly `0.22.0`
- installed-wheel smoke exercises the gateway cost guard and focused public namespaces
- the protected release environment runs the exact wheel under `docs/releases/0.22.0-smoke-policy.json`

The OpenAI and Meta canaries retain the reviewed `0.21.0` model/operation scope. Reusing that scope for `0.22.0` does not turn local tests into live certification; only the protected exact-artifact workflow can produce release evidence for this version.

Capture local candidate evidence with:

```bash
make release-evidence
```

Local or dirty-worktree results are integration evidence. Formal release certification exists only after the PR is merged, the clean `main` commit is tagged once as `v0.22.0`, and the exact artifact passes the protected workflow. Do not create or move the release tag from the PR branch.

## Publication Sequence After The PR

1. Merge the approved PR and wait for the complete `main` CI matrix.
2. Confirm PyPI still has no `0.22.0` files and remote Git has no `v0.22.0` tag.
3. Create the annotated `v0.22.0` tag on the merged `main` commit and push that tag once.
4. Let `publish-pypi.yml` rebuild the candidate, run Postgres/artifact gates, execute the protected OpenAI/Meta exact-wheel smoke, and publish through Trusted Publishing.
5. Verify the PyPI wheel and sdist version/hashes and retain `release-smoke-evidence.json` from the workflow.

## Production Boundary

Applications still own catalog review cadence, regional or negotiated pricing overrides, tenant authorization, telemetry delivery guarantees, cache-directory permissions, retention, and downstream idempotency. Catalog ranking and conservative cost comparison are routing evidence, not provider availability guarantees or invoice calculation.
