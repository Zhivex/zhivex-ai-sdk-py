# 0.18.0 Release Plan

Version `0.18.0` adds a direct Meta Model API adapter and broadens the agent-runtime, evaluation, realtime, model-catalog, and provider-contract surface. The package remains Beta. Meta is a Beta portable provider outside the Tier-1 production set, and native-only or compatibility factories remain Experimental.

## Scope

- Beta portable `create_meta()` support for Muse Spark Chat Completions and Responses, including text, streaming, JSON Schema output, callable and hosted tools, files, continuation, gateway routing, catalog metadata, offline contracts, and opt-in live smoke
- Muse Spark direct catalog entries plus conservative Muse Glimmer and Llama 4 host/open-weight routes without promoting host-dependent capabilities into direct Meta claims
- typed tool decorators with annotation-derived schemas, input/output guardrails, cancellation propagation, bounded agent-group concurrency, member timeouts, fail-fast behavior, shared dependencies, and deterministic idempotency keys
- hardened experimental realtime agents with persisted state, atomic idempotency, durable approval resume, middleware, timeout, run-limit, and cancellation behavior
- finite Wilson pass-rate confidence bounds and sample latency dispersion for evaluation reports and gates
- current Gemini, Qwen, OpenAI, provider-support, public-export, release-artifact, documentation, and smoke contracts

## Stability

The SDK package remains Beta. Existing Stable exports retain their documented compatibility contract. `create_meta()` and its portable surface are Beta and non-Tier-1; its portable badge covers only the capabilities marked in the generated support matrix. Hosted Meta helpers, provider-native clients, workflow graphs, evaluation experiments, and the expanded realtime agent surface retain their Beta or Experimental classifications from `STABILITY.md`.

Bedrock, OpenRouter, and Ollama remain Experimental factories because they are native-only or compatibility providers. Their adapter capabilities must not be read as a portable-support guarantee.

## Required Evidence

- `make check` with public-contract, stability-manifest, support-matrix, provider, agent, workflow, evaluation, realtime, documentation, lint, typing, compilation, and coverage gates
- `make release-check` against the exact clean candidate, including wheel/sdist metadata, isolated install-from-artifact smoke, optional extras, Twine validation, and dependency audits
- existing Postgres run store and workflow contracts plus real PostgreSQL integration coverage for state, idempotency, approvals, cancellation, leases, fencing, restart, and concurrent operations
- strict credentialed installed-wheel generation and agent-tool smoke for OpenAI `gpt-5.6-luna`, Gemini `gemini-3.6-flash`, Qwen `qwen3.8-max`, and Meta Standard `muse-spark-1.2`
- remote CI for Python 3.11 through 3.14 after the release commit is pushed
- release evidence generated from the exact clean release commit; local-source smoke and offline contracts do not establish installed-artifact or exact-SHA certification

Authenticated integration runs on `2026-08-14` passed deterministic generation and an agent tool loop for all four selected models above, first from local source and then from a locally built `zhivex-ai-sdk==0.18.0` wheel installed into an isolated environment. The release changes were still uncommitted, so these results satisfy the local source/artifact integration check but not the immutable exact-SHA release requirement.

Capture the candidate record with:

```bash
make release-evidence
```

## Production Boundary

Meta Standard and Contributor have materially different data-use terms; sensitive workloads must not select Contributor implicitly. Model and region availability, rate limits, retention, zero-data-retention approval, and hosted-tool behavior remain upstream account concerns that require deployment-specific validation.

Tool guardrails, workflow leases, cancellation records, and SDK idempotency controls do not replace application authorization, tenant isolation, audit policy, destination idempotency, outbox/reconciliation, or external side-effect verification. Protocol and playground surfaces still require an application-owned authentication, policy, persistence, rate-limit, and network boundary before public exposure.
