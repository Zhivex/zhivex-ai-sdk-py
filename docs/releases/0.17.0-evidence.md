## Unsatisfied Qwen Requirement

The `0.17.0` release plan required a strict credentialed Qwen smoke for the intended GA model before publication. The publication workflow selected only OpenAI, and the smoke runner at the released commit required at least one provider rather than every provider named by the release scope. Consequently:

- the release has real installed-wheel evidence for OpenAI;
- the release has offline contract, provider, workflow, and artifact evidence for the Qwen implementation;
- the release has **no live Qwen 3.8 Max certification**;
- the required pre-publication Qwen evidence was **not satisfied**.

Running Qwen later can establish current compatibility, but cannot turn that later observation into evidence that existed before publication. This reconstruction intentionally makes no such retroactive claim.

## Reconstruction Limits

- No clean-candidate `docs/releases/0.17.0-evidence.md` was generated before publication, so this file cannot reproduce local tool versions, sanitized command output, or pre-publication working-tree state from `make release-evidence`.
- Ignored local files under `dist/` are not evidence for the published artifacts unless their hashes match PyPI. The artifacts observed during this reconstruction did not match the published hashes and included an older Qwen module, so they were excluded from the release record.
- Offline provider tests validate SDK-owned request and response contracts. They are not live certification of provider availability, model behavior, account permissions, quotas, or region-specific features.
