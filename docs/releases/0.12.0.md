# Zhivex AI SDK 0.12.0 Release Plan

`0.12.0` is the current-provider contracts beta release. It keeps the package in Beta while aligning tier-1 model guidance and provider-specific request handling with the latest verified APIs.

## Release Theme

Current provider support without widening the stable surface:

- refresh recommended model IDs for OpenAI, Azure OpenAI, Anthropic, Gemini, Vertex, Qwen, and Kimi/Moonshot
- model current reasoning, hosted-tool, structured-output, and nested tool-calling contracts explicitly
- preserve the distinction between portable SDK behavior and provider-native beta features
- keep the production agent runtime, Postgres run store, and public foundation contracts compatible with `0.11.0`

## Included Work

- Version metadata moves to `0.12.0` while the package remains `Beta`.
- OpenAI and Azure OpenAI catalog guidance covers GPT-5.6 Sol, Terra, and Luna, with GPT-5.6 Terra used in recommended examples.
- OpenAI beta programmatic tool calling supports callable-tool `output_schema`, `allowed_callers`, nested caller linkage, and replay-safe program outputs.
- Anthropic guidance covers restricted-access Claude Mythos 5 and current 2026 web search, web fetch, and code execution tool versions.
- Anthropic adaptive-thinking and mid-conversation system-message validation follows the current supported model families.
- Qwen Responses uses the current `/compatible-mode/v1/responses` route, sends the documented seven-level `reasoning.effort` contract, maps mixed text/image content correctly, validates hosted-tool combinations before consuming provider quota, and safely downloads official signed TTS output over HTTPS.
- Kimi K3 uses its distinct always-on reasoning contract, including supported effort levels, multimodal input, strict structured output, sampling constraints, and reasoning continuation.
- Gemini and Vertex catalog guidance covers current Gemini Omni Flash, Flash-Lite Image, Veo, and supported Imagen models while removing retired recommendations.
- Provider metadata survives tool-result serialization so nested programmatic calls retain caller linkage during agent execution and replay.
- Remote HTTP and MCP tools require approval by default unless an exact tool is explicitly trusted; server annotations cannot grant trust by themselves.
- Agent tool timeouts terminate the loop with `ToolExecutionOutcomeUnknown` and a stable idempotency key because a synchronous side effect may complete after the caller times out.
- Durable run stores use schema-versioned compare-and-swap updates, atomic cancellation, unique idempotency claims, and exact-token recovery for abandoned approval resumes. A cancellation that wins an active-worker race surfaces as `AgentRunCancelled`.
- Event callback failures surface as `AgentEventDeliveryError` without rewriting an already committed terminal run.

## Stability Position

This release does not declare `1.0` or promote new provider-native surfaces to stable:

- stable: public foundation APIs, tier-1 provider factories, gateway contracts, main SDK errors, core agent entrypoints, Postgres memory/checkpoint stores, Postgres run store, run-state serialization, cancellation, replay, run snapshots, and durable approval resume
- beta: local run stores, workflow agents, observability helpers, native provider clients, hosted tools, programmatic tool calling, provider-managed approvals, packaged skills, evaluation reports, trace artifacts, safety/redaction/budget helpers, and production examples
- experimental: realtime/live voice

## Release Evidence

Before publishing, run:

```bash
make release-evidence
```

The release candidate must also pass `make check` and `make release-check`, including wheel and source-distribution installation, optional extras, dependency audit, package metadata validation, and artifact verification for version `0.12.0`.

Live provider smoke can be run locally when credentials, account access, regional availability, and model IDs are configured:

```bash
ZHIVEX_SMOKE_PROVIDERS=openai,anthropic,azure-openai,gemini,vertex,qwen,kimi,vllm make smoke
```

Skipped live smoke providers should identify the missing credential, model configuration, access grant, or regional availability constraint.

For Qwen release candidates, use the current Singapore base URL unless a workspace-specific domain is configured, and include the optional embedding and TTS models when the account supports them. Batch completion is a separate regional service check: Singapore accepts the documented stable model aliases rather than every realtime Qwen3.x model ID.

Before publishing the agent-first release, validate at least one strict tool-loop smoke against a configured tier-1 provider:

```bash
ZHIVEX_SMOKE_PROVIDERS=openai make smoke-agents
```

This gate only succeeds after `run_agent(...)` calls a real local validation tool, consumes the expected tool result, and finishes the agent loop. Both publish workflows now block on a no-OIDC `release-smoke` environment job that installs the verified wheel, requires `ZHIVEX_RELEASE_SMOKE_PROVIDERS`, and uses matching environment model variables plus `ZHIVEX_RELEASE_*` credential secrets. Configure at least one tier-1 provider there; the Trusted Publisher job cannot start if the smoke is skipped or fails. The Postgres integration suite is separately enabled by `ZHIVEX_TEST_POSTGRES_DSN` and exercises memory, checkpoints, full run persistence, concurrent idempotency claims, and concurrent approval claims.

## Non-Goals

- no `1.0` declaration
- no new tier-1 provider promotion
- no stability promotion for provider-native hosted tools or programmatic tool calling
- no assumption that restricted-access or preview models are available to every account or region
- no removal of older compatible model IDs solely because newer recommendations exist
