### Corrections and compatibility

- Persist guarded caller input and redacted retained history consistently in
  sessions, memory, summaries, checkpoints and run snapshots. Caller ownership
  survives guardrail removals, replacements, additions and reordering without
  persisting runtime instructions. Output guardrails cover all responses across
  provider-managed approval continuations, excluding prior history and opaque
  approval responses.
- Check cumulative safety budgets between model/tool operations, across direct
  handoffs and optional local child runs. Preserve child token accounting and
  stop subsequent dispatch after a budget tripwire. Calls already started can
  exceed a token threshold; this does not impose a hard monetary guarantee.
- Close provider iterators on cancellation, timeout and event-delivery failure.
  The unused private generation replay retains one event; public replay defaults
  and complete collected output remain compatible. Final text and message parts
  can still grow with output.

No migration is required for ordinary public agent calls. Custom input guardrails
that assign a replacement message list must retain existing runtime/context
messages, including unchanged clones, so caller ownership remains identifiable.
An ambiguous rewrite spanning both context and caller input fails before model
dispatch. To intentionally replace the request with caller input, clear its
message list and append the new caller messages. Redaction policies cover
normalized message content; application metadata and opaque provider data still
need application-owned retention rules. See the [agent guide](../AGENTS.md).

### Release controls

Metadata, lockfile and both publication workflows select `0.28.4`. The
[new smoke policy](0.28.4-smoke-policy.json) changes only the package version from
the 0.28.3 policy. Historical wheels and certification evidence do not certify
the new artifact. Installed wheel/sdist checks, mandatory Postgres consumer
checks, dependency security audits and distribution metadata checks remain
required. Certification evidence records the installed wheel hash, package
version, source revision and GitHub workflow identity.

The protected `release-smoke` job requires OpenAI `gpt-6-luna` generation and
agent-tool checks, plus Meta `muse-spark-1.2-contributor` generation, streaming,
structured output, application-supplied portable retrieval and agent-tool checks.
Meta Contributor evidence does not certify Meta Standard. Both selected providers
must execute successfully; missing credentials or failed evidence block
publication. The `pypi` job can run only after build and live smoke succeed and
uses the existing OIDC Trusted Publisher.

### Proposed live campaign for later approval

One protected workflow run selects only these two providers and uses fixed
synthetic markers and a local nonce-validation tool. OpenAI uses reasoning
effort `none`; Meta uses `low`. The existing runner settings are:

| Operation | OpenAI output-token setting | Meta output-token setting |
| --- | --- | --- |
| Generation | 128 | 512 |
| Streaming / structured output / portable retrieval | Not selected | 512 per operation |
| Agent loop | 512 per model step, at most 3 steps | 1,024 per model step, at most 3 steps |

Each model operation permits one SDK retry. Non-agent model attempts have a
20-second timeout; model attempts within each agent loop have a 30-second timeout.
The live job has a 15-minute timeout. These are execution/output bounds, not a
campaign price cap;
input tokens, provider billing and an already-started request still matter. Any
additional workflow attempt or TestPyPI campaign is a separate paid execution
requiring authorization. Preparation does not run these calls or change secrets.
