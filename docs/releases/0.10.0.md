# Zhivex AI SDK 0.10.0 Release Plan

`0.10.0` is a production-readiness beta release and GA-candidate groundwork. It keeps the package in Beta while promoting the most defensible operational agent runtime pieces into the documented stable surface.

## Release Theme

GA candidate groundwork without expanding provider scope:

- keep the stable surface predictable while the package stays in `0.x`
- make production run-state, idempotency, replay, and cancellation contracts stable where they are backed by Postgres
- correct production guidance drift before publishing
- keep experimental and provider-native areas clearly labeled

## Included Work

- Version metadata moves to `0.10.0` while the package remains `Beta`.
- The stable agent surface now includes the Postgres run store, run-state serialization, cancellation helpers, replay helpers, and run snapshots.
- In-memory and SQLite run stores remain beta/local-development choices.
- Workflow agents, packaged skills, provider-managed approvals, evaluation reports, trace artifacts, safety/redaction/budget helpers, and realtime/live voice remain outside the stable surface.
- Production API docs list the full tier-1 provider set: OpenAI, Anthropic, Azure OpenAI, Gemini, Vertex, Qwen, Kimi/Moonshot, and vLLM.
- Gateway docs now match the `GatewayConfig.fallback_on_refusal=False` default.

## Stability Position

This release still does not declare `1.0`. The stable additions are limited to production run-state and replay APIs that already have offline contract coverage:

- stable: public foundation APIs, stable provider factories, gateway contracts, main SDK errors, core agent entrypoints, Postgres memory/checkpoint stores, Postgres run store, run-state serialization, cancellation, replay, and run snapshots
- beta: local run stores, workflows, observability helpers, native provider clients, hosted tools, packaged skills, evaluation reports, trace artifacts, safety/redaction/budget helpers, and production examples
- experimental: realtime/live voice

## Release Evidence

Before publishing, run:

```bash
make release-evidence
```

The generated evidence file should be committed or attached to the release notes when the gates are run for a publish candidate. Optional live provider smoke should still be recorded separately because it depends on configured credentials and model availability:

```bash
ZHIVEX_SMOKE_PROVIDERS=openai,anthropic,azure-openai,gemini,vertex,qwen,kimi,vllm make smoke
```

Skipped live smoke providers should be recorded with the missing credential or model environment variable, not as generic skips.

## Non-Goals

- no `1.0` declaration
- no DeepSeek tier-1 promotion
- no new provider or model catalog refresh unless required by a separate verified provider-support change
- no workflow, packaged-skill, provider-managed approval, safety policy, or realtime stability promotion
