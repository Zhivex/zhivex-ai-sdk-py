# Zhivex AI SDK 0.9.0 Release Plan

`0.9.0` is a beta adoption release. It does not attempt to declare the SDK `1.0` ready; it tightens the path for production backends that already depend on the documented stable surface.

## Release Theme

Production agent adoption with explicit runtime evidence:

- keep the stable surface predictable while the package stays in `0.x`
- make gateway routing safer to operate in backend services
- document release evidence as a repeatable artifact, not an informal checklist
- add production-style examples for API and worker boundaries

## Included Work

- Version metadata moves to `0.9.0` while the package remains `Beta`.
- Gateway routing emits `on_attempt` events for skipped targets as well as executed attempts.
- Gateway routing can fail fast on missing provider adapters with `GatewayConfig(fail_on_missing_adapter=True)`.
- Anthropic native models support Claude Opus 4.8 (`claude-opus-4-8`) with `ReasoningConfig(effort=...)`, adaptive thinking for Opus 4.7/4.8, and Opus 4.8 mid-conversation system messages.
- `scripts/collect_release_evidence.py` records the release gate commands and output into `docs/releases/<version>-evidence.md`.
- `make release-evidence` runs the evidence collector.
- Production examples show a FastAPI agent boundary and a worker resume/idempotency boundary.

## Stability Position

No new APIs are promoted to stable in this release. The intent is to make beta operational surfaces easier to adopt without overstating guarantees:

- stable: public foundation APIs, stable provider factories, gateway contracts, main SDK errors, and core agent entrypoints already listed in `STABILITY.md`
- beta: run stores, workflows, observability helpers, native provider clients, hosted tools, packaged skills, and production examples
- experimental: realtime/live voice

## Release Evidence

Before publishing, run:

```bash
make release-evidence
```

The generated evidence file should be committed or attached to the release notes when the gates are run for a publish candidate. Optional live provider smoke should still be recorded separately because it depends on configured credentials and model availability:

```bash
ZHIVEX_SMOKE_PROVIDERS=openai,anthropic,azure-openai,gemini,vertex,qwen,kimi,vllm make smoke
```

Skipped live smoke providers should be recorded with the missing credential or model environment variable, not as generic skips.

## Non-Goals

- no `1.0` declaration
- no broad stable-surface expansion
- no silent provider fallback policy changes for existing gateway users
- no new tier-1 provider unless its contract, docs, tests, and smoke setup are completed together
