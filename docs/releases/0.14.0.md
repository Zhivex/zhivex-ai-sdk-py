# Zhivex AI SDK 0.14.0 Release Plan

`0.14.0` makes the stable agent runtime easier to type, extend, and integrate while the package remains Beta.

## Included Work

- `Agent[DepsT, OutputT]` links typed runtime dependencies, dynamic instructions, tools, and terminal outputs.
- `AgentContext[DepsT]` and `ToolExecutionContext[DepsT]` expose process-local dependencies without persisting or serializing them.
- `AgentRunResult.output` and `AgentStreamResult.collect()` validate the root agent's `output_type`; `result.text` remains compatible.
- `output_mode="auto"` uses native structured output where supported and schema-guided prompted JSON otherwise.
- Sync and async dynamic instructions resolve once per agent segment and are removed from stored session transcripts.
- `AgentHooks` covers agent, physical model-call, tool, approval, handoff, and error lifecycle points with deterministic nesting.
- `AgentMiddleware` and `AgentRunRequest` wrap complete root runs at runtime, call, or agent scope.
- Direct handoffs share the root dependency and output contracts; child agents invoked as native tools start their own output contract.
- Run, stream, session resume, approval resume, idempotent reuse, subagent-tool, and experimental realtime paths have explicit typed-output/dependency behavior.
- Public `zhivex_ai` imports retain mypy inference and installed-wheel verification covers the new exports.

## Compatibility And Security

- Existing string `instructions`, positional `Agent(...)` construction, `result.text`, and untyped tools continue to work.
- Dependencies can contain application clients or credentials. They are hidden from context reprs and excluded from durable run state, checkpoints, traces, and serialized transport contexts.
- Applications must provide `deps=` again for resume and must not copy dependency objects into hook logs or metadata.
- The root agent's `output_type` governs the terminal response after direct handoffs.
- Experimental realtime runs support prompted typed output and reject native typed-output mode; realtime model-event traffic does not emit `on_model_*` hooks.

## Stability Position

- Stable: generic agent/context/result contracts, dynamic instructions, lifecycle hooks, run middleware, top-level typing declarations, and `AgentObserver`.
- Beta: native subagent-tool helpers, local run stores, evaluation/trace artifacts, declarative workflows, and provider-managed approvals.
- Experimental: realtime/live agents.

## Release Evidence

Before publishing, run:

```bash
make test-agent-contracts
make test-agents
make test-contract
make test-docs
make typecheck
make check
make release-check
make release-evidence
```

Verify the release tag against package metadata:

```bash
.venv/bin/python scripts/verify_release_tag.py --tag v0.14.0
```

When provider and Postgres credentials are configured, validate the installed wheel with strict agent smoke enabled. A skipped provider or database integration is not live certification.

The release candidate must also pass the Postgres run store integration suite for idempotency, durable approvals, resume, and terminal-state behavior.
