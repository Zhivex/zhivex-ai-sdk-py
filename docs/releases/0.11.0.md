# Zhivex AI SDK 0.11.0 Release Plan

`0.11.0` is the production agent-apps beta release. It keeps the package in Beta while making durable human-in-the-loop agent runs, approval resume, and UI approval streaming part of the production-oriented agent story.

## Release Theme

Agent apps ready for production integration:

- keep the stable runtime and Postgres run store foundation from `0.10.0`
- add a durable approval lifecycle for local tools that need human authorization
- expose approval state through run stores and UI-message streams
- keep provider-native hosted approvals, workflow agents, packaged skills, and realtime/live voice clearly scoped outside the stable core

## Included Work

- Version metadata moves to `0.11.0` while the package remains `Beta`.
- `ApprovalDecision.require_human(...)` can suspend an agent run before an approved tool executes.
- Suspended runs persist `AgentRunState(status="suspended")` plus `PendingApproval` entries in the configured run store.
- `get_pending_agent_approvals(...)` lists the pending approval queue for a suspended run.
- `resume_agent_run(...)` resolves an approval, executes or denies the pending tool, continues the model loop, links the resumed child run, and updates the original suspended run with final output metadata.
- `UIMessageToolApprovalChunk` preserves approval events in UI/SSE streams.
- Postgres run store remains the production-backed durable store for this stable approval lifecycle; in-memory and SQLite stores remain useful beta/local-development choices.
- Gemini callable-tool schemas are normalized for live agent tool loops, including strict Pydantic schemas that emit unsupported JSON Schema keywords.

## Stability Position

This release still does not declare `1.0`. The stable additions are limited to the agent approval lifecycle pieces backed by existing run-state and run-store contracts:

- stable: public foundation APIs, stable provider factories, gateway contracts, main SDK errors, core agent entrypoints, Postgres memory/checkpoint stores, Postgres run store, run-state serialization, cancellation, replay, run snapshots, durable pending approvals, approval resume, and approval events
- beta: local run stores, workflow agents, observability helpers, native provider clients, hosted tools, provider-managed approvals, packaged skills, evaluation reports, trace artifacts, safety/redaction/budget helpers, UI approval chunks, and production examples
- experimental: realtime/live voice

## Release Evidence

Before publishing, run:

```bash
make release-evidence
```

The generated evidence file should be committed or attached to the release notes when the gates are run for a publish candidate. Optional live provider smoke should still be recorded separately because it depends on configured credentials and model availability:

```bash
ZHIVEX_SMOKE_PROVIDERS=openai,anthropic,azure-openai,gemini,vertex,qwen,kimi,vllm make smoke
```

Skipped live smoke providers should be recorded with the missing credential or model environment variable, not as generic skips.

## Non-Goals

- no `1.0` declaration
- no DeepSeek tier-1 promotion
- no new provider or model catalog refresh unless required by a separate verified provider-support change
- no workflow-agent, packaged-skill, provider-managed approval, safety-policy, or realtime stability promotion
