# 0.17.0 Release Plan

Version `0.17.0` combines Qwen 3.8 Max support with durable-workflow hardening and a narrower, more coherent Stable contract. The package remains Beta; this release does not graduate workflow graphs or external workflow-engine adapters as a block.

## Scope

- pay-as-you-go GA `qwen3.8-max` support across portable text, streaming, reasoning, vision, functions, and documented hosted tools, with operation-aware Chat Completions fallbacks
- explicit workflow step/edge `definition_revision` values for application-owned semantic identity
- typed workflow conflicts, lease loss, definition mismatch, missing-run, and invalid-interrupt failures
- atomic lease validation plus checkpoint append for built-in in-memory, SQLite, and Postgres backends
- Postgres server-clock lease decisions, bounded or application-owned pools, lifecycle controls, namespaces, and checked backend schema metadata
- schema-v1 compatibility fixtures from `0.15.0`, including canonical reserialization, resume, fork, and legacy digest coverage
- idempotent reconciliation for concurrent workflow forks and contention coverage for cancel/resume/fork paths
- promotion of unavoidable portable foundation/result DTOs used directly by Stable APIs

## Stability

The portable model/message/result/usage contracts named in `STABILITY.md` move to Stable because applications cannot consume the existing Stable foundation and agent APIs without them. Provider-native helpers, workflow graphs, checkpoint/lease managers, resume/fork/cancel, and callback adapters remain Beta. DBOS, Temporal, Prefect, and Restate factories remain application-owned callback contracts rather than certified engine integrations.

## Required Evidence

- `make check` with public-contract, stability-manifest, compatibility, workflow, provider, documentation, lint, typing, compilation, and coverage gates
- `make release-check` against the exact clean candidate, including wheel/sdist metadata, install-from-artifact smoke, optional extras, Twine, and dependency audits
- existing Postgres run store contracts plus real PostgreSQL workflow integration covering persistence, fencing, server clock, namespace isolation, shared/owned pool lifecycle, restart, cancellation, concurrent resume, and concurrent fork behavior
- strict credentialed Qwen smoke for the intended GA model before publication; offline contracts are not a substitute for live provider behavior
- remote CI for Python 3.11 through 3.14 after the branch is pushed
- release evidence generated from the exact clean commit only; do not reuse the `0.16.0` evidence or artifact hashes

Capture the exact candidate record with:

```bash
make release-evidence
```

## Production Boundary

Workflow leases protect orchestration writes but cannot make external effects atomic. Applications still need destination idempotency, an outbox, downstream fencing, or reconciliation. Namespaces partition SDK keys but do not replace database authorization or tenant policy. External engine adapters require their own worker, persistence, retry, upgrade, and end-to-end certification evidence.
