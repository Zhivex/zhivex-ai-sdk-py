# 0.25.0 Release Plan

Version `0.25.0` adds Qwen3.8 Omni Flash multimodal support. The package remains Beta;
existing Stable imports and compatibility guarantees do not change.

## Scope

- Mixed text, image, audio, and video input; text and reasoning streaming; spatial audio.
- Callable tools, agent replay, and hosted web search. Reasoning budgets use Chat
  Completions; thinking with search transparently collects the required stream.
- Model-specific catalog metadata and early rejection of unsupported hosted tools,
  non-user media, speech output, and native JSON Schema. JSON output uses prompting.
- Synthetic smoke fixtures and an installed-wheel smoke that verifies SDK bytes
  against the supplied wheel before calling the provider.

## Validation

Use uv 0.12.4 and `make release-check`. This checks the lock, coverage, public
contracts, typing, support/certification metadata, wheel and sdist installs, all
optional extras, dependency audits, and distribution metadata. The Postgres run store
and installed workflow smoke must also pass against PostgreSQL 16. CI runs Python
3.11–3.14 and the minimum/latest dependency matrix.

`make release-evidence` can collect a fresh local candidate report. The release
preparation report is [0.25.0-evidence.md](0.25.0-evidence.md). Evidence from 0.23.0
and 0.24.0 is historical and does not certify this candidate.

The publish workflows use `0.25.0-smoke-policy.json`, requiring fresh OpenAI Luna
and Meta Contributor canaries from the exact installed release wheel. Qwen Omni's
local installed-wheel evidence is additional integration evidence, not protected
release certification. No Qwen credential is currently configured in the protected
`release-smoke` environment; the existing publication policy is unchanged.

To repeat Omni verification, install the wheel in a fresh virtual environment and run:

```sh
ZHIVEX_SMOKE_USE_INSTALLED=1 /path/to/venv/bin/python -I scripts/smoke_qwen_omni.py \
  --wheel dist/zhivex_ai_sdk-0.25.0-py3-none-any.whl \
  --report docs/releases/0.25.0-qwen-omni-installed.json
```

Pass `QWEN_API_KEY` or `DASHSCOPE_API_KEY` through the environment. The default
video fixture is synthetic and bundled in `tests/fixtures`; all other media is
synthesized in memory. Reports omit credentials and model responses.

## Publication

1. Review and merge the release preparation, then wait for all main CI gates.
2. Recheck PyPI and the remote tag; 0.25.0 was absent from both during preparation.
3. Create annotated tag `v0.25.0` on the approved clean main commit and push it once.
4. The protected workflow rebuilds, validates, live-tests, and publishes through
   Trusted Publishing. Verify registry hashes against those workflow artifacts.
5. Retain the exact-artifact reports. Local candidate hashes are not publication proof.

This preparation does not create a release tag or publish to PyPI/TestPyPI.
