# 0.25.0 release plan

Version `0.25.0` adds the September provider refresh, native OpenAI managed Agents/GPT-Live clients and Anthropic signed compaction. The distribution remains Beta; new native APIs preserve their documented Beta/Experimental scope.

## Compatibility and migration

- Prefer DeepSeek `deepseek-flash` for V4.1. The two legacy Flash routes remain accepted and separately cataloged as deprecated; upstream changes their implementation and billing. User-image vision and current thinking/top-p behavior are covered. V4 Pro remains text-only.
- OpenAI managed Agents and GPT-Live use explicit native clients. GPT-Live is a separate `live` API surface; the existing Realtime client is not its transport. Install the `realtime` extra for WebSockets. Callers own delegated work, approvals and durable effects; explicit finalization is distinct from releasing the socket.
- Anthropic signed compaction preserves opaque blocks and signatures. Applications replace history only after receiving a usable summary; incompatible parameters fail locally.
- Gemini 3.8 Live supports standard and Extended Thinking audio, validates thinking/tool settings and preserves combined audio/tool events. Meta Spark 1.3 is a Beta model extension without promoting the Stable 1.2 cohort.
- Catalog additions include GPT Image 2.5 and Lyria 3.5. `ModelApiSurface` gains `live`, and native support metadata gains additive flags. Existing Stable imports remain available.

See [the detailed source review and examples](../MODEL_REFRESH_2026_09_16.md).

## Publication procedure

1. Review and merge the release PR; require every CI gate to pass, including PostgreSQL and dependency compatibility.
2. Confirm PyPI 0.25.0 and remote tag `v0.25.0` remain absent immediately before release.
3. Create an annotated `v0.25.0` tag on the approved clean main commit and push it once.
4. The protected release workflow builds distributions, executes exact-wheel canaries and validates evidence, then publishes through Trusted Publishing.
5. Verify PyPI artifact hashes and retain workflow evidence. Do not retag or replay publication without checking registry state first.

PR preparation does not create a release tag, merge, publish to PyPI or run the protected publication workflow.

## Qwen Omni addition before publication

PR #45 reserved version 0.25.0 on main but did not publish or tag it. The Omni
addition stays in that same version and preserves the September provider refresh.
The combined package requires a fresh build; previous wheel evidence does not
certify the new bytes.

Qwen3.8 Omni Flash adds mixed text/image/audio/video input, spatial audio,
streaming, reasoning, function calls, and web search. Budget-based thinking uses
Chat Completions and collects streaming internally when search requires it.
Omni native multimodal support remains Beta; native JSON Schema, speech output,
and realtime are not claimed. Existing Stable contracts do not change.

See [combined candidate evidence](0.25.0-omni-evidence.md) and the
[installed-wheel Omni report](0.25.0-qwen-omni-installed.json). For a fresh run,
install the wheel in an isolated environment and run:

```sh
ZHIVEX_SMOKE_USE_INSTALLED=1 /path/to/venv/bin/python -I scripts/smoke_qwen_omni.py \
  --wheel dist/zhivex_ai_sdk-0.25.0-py3-none-any.whl \
  --report docs/releases/0.25.0-qwen-omni-installed.json
```

Pass QWEN_API_KEY or DASHSCOPE_API_KEY through the environment. Media is synthetic;
the MP4 fixture is bundled under tests/fixtures. The runner verifies installed
SDK bytes against the wheel and writes only redacted operation outcomes.
The protected publication policy still requires fresh OpenAI/Meta canaries from
its own built artifact; local Omni smoke is not protected release certification.
