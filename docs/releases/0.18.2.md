# 0.18.2 Release Plan

Version `0.18.2` is the publisher recovery for the unpublished `v0.18.1` workflow run. It preserves the `0.18.1` SDK behavior and stability classifications while updating the commit-pinned PyPI publisher to `v1.14.2`, whose Twine 7 runtime accepts Core Metadata 2.5.

## Scope

- pin `pypa/gh-action-pypi-publish` `v1.14.2` by its verified commit in both PyPI and TestPyPI workflows
- retain the complete `0.18.1` release gates, protected installed-wheel provider smoke, and public SDK contract
- add a regression contract covering the Metadata 2.5-compatible publisher in both publication workflows
- publish a new patch version without moving or reusing the failed `v0.18.0` or `v0.18.1` tags

## Required Evidence

- `make check` with public-contract, stability-manifest, support-matrix, provider, agent, workflow, evaluation, realtime, documentation, lint, typing, compilation, and coverage gates
- `make release-check` against the exact clean candidate, including wheel/sdist metadata, isolated install-from-artifact smoke, optional extras, Twine validation, and both dependency audits
- existing Postgres run store and workflow contracts plus real PostgreSQL integration coverage for state, idempotency, approvals, cancellation, leases, fencing, restart, and concurrent operations
- strict credentialed installed-wheel generation and agent-tool smoke for each configured release provider
- remote CI for Python 3.11 through 3.14 after the recovery commit is pushed
- successful Trusted Publishing from the immutable `v0.18.2` tag and registry verification of both wheel and sdist
- release evidence generated from the exact clean release commit; local validation does not establish remote CI, live-provider, or registry publication

Capture the candidate record with:

```bash
make release-evidence
```

## Recovery Boundary

The `v0.18.1` workflow passed its build gates, artifact upload, and protected live-agent smoke, then stopped in the publisher's pre-upload metadata validation because the older pinned action did not accept Core Metadata 2.5. No `0.18.1` files reached PyPI. Do not move or reuse the tag; publish only from a new `v0.18.2` tag whose commit passes the complete aligned workflow.

## Production Boundary

The SDK remains Beta. Existing Stable exports retain their documented compatibility contract. Meta remains Beta and non-Tier-1; Bedrock, OpenRouter, and Ollama remain Experimental factories. Workflow graphs, evaluation experiments, hosted protocol adapters, and realtime agent surfaces retain their existing Beta or Experimental classifications.

Tool guardrails, workflow leases, cancellation records, and SDK idempotency controls do not replace application authorization, tenant isolation, audit policy, destination idempotency, outbox/reconciliation, or external side-effect verification.
